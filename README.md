# PetFeed – сервис учета кормления животных

Учебное приложение для учета кормления животных в приюте или питомнике.
Показывает суточную норму корма каждого животного, историю кормлений и
сколько корма еще можно дать сегодня.

Основное правило: сумма кормлений животного за день не может превышать его
суточную норму. Отмененное кормление в норму не входит.

## Технологии
Python 3, Django 5.2, SQLite (доступ к данным через Django ORM), HTML, CSS,
Bootstrap 5, Unidecode, Pillow, Django Debug Toolbar, pytest, flake8.

## Модели данных
- **Animal** (`animals`) – кличка, вид, суточная норма корма (г), slug для
  адреса страницы (`/animals/barsik-1/`) и признак «большая норма»
  (норма от 500 г, вычисляется базой данных через `GeneratedField`),
  фото;
- **Employee** (`employees`) – сотрудник: имя, email (уникальный);
- **Feeding** (`feedings`) – кормление: животное, сотрудник, дата, корм,
  порция (г), статус, комментарий.

Статусы кормления: «Запланировано», «Выполнено», «Отменено». В суточную
норму входят все кормления, кроме отмененных. Частые выборки собраны в
менеджере: `Feeding.objects.active()`, `.planned()`, `.done()`,
`.cancelled()`, `.for_date(дата)`, `.fed_amount()`.

`Feeding` связан с `Animal` и `Employee` через `ForeignKey`
(`on_delete=PROTECT`, `related_name="feedings"`): животное или сотрудника
нельзя удалить, пока на них ссылаются кормления.

## Структура
```text

data/                             JSON-файлы и исходная база petfeed.sqlite
```

## Запуск
```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python db/import_sqlite_to_orm.py
python manage.py runserver
```
Сайт откроется по адресу http://127.0.0.1:8000/.
Консольная версия: `python main.py`.

Административная панель – http://127.0.0.1:8000/admin/. Пользователя для
входа нужно создать один раз: `python manage.py createsuperuser`.
В режиме разработки (`DEBUG = True`) на страницах сайта выводится панель
Django Debug Toolbar с SQL-запросами страницы.

## База данных
Django работает с базой `db.sqlite3`, ее таблицы создаются миграциями.
Файл `db.sqlite3` в репозиторий не входит.

Исходные данные лежат в базе ПР7 `data/petfeed.sqlite`. Скрипт
`db/import_sqlite_to_orm.py` переносит из нее животных, сотрудников и
кормления с сохранением идентификаторов; запускать можно повторно.
Посмотреть структуру исходной базы: `python db/inspect_source_db.py`.

## Страницы
- главная;
- список животных: поиск по кличке и виду, фильтр по норме, сортировка;
- карточка животного с остатком нормы на выбранную дату;
- «Кого можно покормить» на дату;
- загрузка фото животного;
- журнал кормлений: форма фильтра по статусу, дате, животному и
  сотруднику, сортировка и постраничный вывод;
- планирование и редактирование кормления, отметка о выполнении и отмена;
- статистика.

## Формы
- фильтр журнала – обычная форма `forms.Form`, данные передаются GET;
- кормление создается и редактируется через `ModelForm`. Проверяется, что
  дата не в прошлом, порция не больше 2000 г, название корма содержит буквы
  и общая сумма за день не превышает суточную норму животного;
- редактировать можно только запланированные кормления; выполнение и
  отмена – POST-запросы с CSRF-токеном;
- фото животного загружается формой с `enctype="multipart/form-data"`,
  принимаются изображения до 2 МБ. Файлы сохраняются в папку `media/`
  (в репозиторий не входит).

## Административная панель
- животные: поиск по кличке и виду, фильтр по виду и «большой норме»,
  правка нормы прямо в списке, кормления животного на его странице;
- сотрудники: поиск по имени и email, кормления сотрудника;
- кормления: фильтры по статусу, дате, виду животного и сотруднику, поиск,
  действия «Отметить выполненными» и «Отменить».
